# وثيقة متطلبات المنتج (PRD)

## أدرك عمرك — تطبيق الهاتف: حماية التركيز والتنفيذ (Adrik Mobile v2)

* **الإصدار:** 2.0.0
* **التاريخ:** أكتوبر 2026
* **نوع التطبيق:** Android APK شخصي (Expo SDK 57 / React Native 0.86.3)
* **الحالة:** معتمد — جاهز للتنفيذ البرمجي (Approved for Development)

---

## 1. نظرة عامة على المشروع (Executive Summary)

### 1.1 بيان المشكلة (Problem Statement)

1. المؤقت يتوقف عند الخروج من التطبيق، ولا يوجد إشعار يحمل اسم المهمة الجارية.
2. لا توجد حماية من المشتتات، ولا مسار واضح للعودة إلى العمل بعد التشتت.
3. الأولويات اليومية منفصلة عن مهام المشاريع.
4. لا يوجد قياس فعلي للإنجاز ولا ضبط ذاتي لحمل العمل اليومي.
5. حجم حزمة APK كبير.
6. لا يوجد نسخ احتياطي للبيانات.

### 1.2 الحل المقترح (The Solution)

تحويل التطبيق إلى نظام تنفيذ **يحمي التركيز**، و**يعيد المستخدم عند التشتت بخطوات صغيرة**، و**يربط الأولويات بمهام المشاريع**، و**يضبط الحمل اليومي آلياً** بناءً على الأداء الفعلي.

### 1.3 الجمهور المستهدف (Target Persona)

مستخدم واحد بنمط **INTJ-A** — استخدام شخصي.
المراجع: `docs/INTJ_PROFILE.md` · `docs/USAGE_PROTOCOL_INTJ.md`.

## 2. المبادئ الحاكمة للمنتج (Design & Behavioral Principles)

1. **أقصى إنجاز بكفاءة عالية:** كل ميزة تُقاس بأثرها على دقائق العمل العميق المنجز.
2. **لا تغيير صامت:** كل ضبط آلي يُعرض اقتراحاً يُقبل أو يُرفض بنقرة.
3. **العودة أهم من عدم السقوط:** التشتت حدث متوقع؛ المهم زمن العودة.
4. **خطوة واحدة بنقرة واحدة:** كل مسار تفاعلي مقسّم لخطوات لا تتطلب تفكيراً.
5. **ثوابت لا تتغير:** `drain` واحدة يومياً · تنبيه 30% · قفل Vault 48 ساعة بلا تجاوز · كتل 90/60/45 و20 للانهيار · DoD إلزامي دائماً · نبرة المدرّب · مفتاح المدرّب الذكي كما هو.

## 3. المعمارية التقنية (Technical Stack)

* **Framework:** Expo ~57 / Expo Router / React Native 0.86.3 / TypeScript.
* **State Management:** Zustand 5 + AsyncStorage.
* **Notifications:** `@notifee/react-native` (إشعار ثابت + `showChronometer` + قناة High Importance).
* **Screen:** `expo-keep-awake`.
* **Build:** `expo-build-properties` + EAS profile `personal`.
* **Sync:** `src/lib/sync/core.ts` يبقى مطابقاً بايت-ببايت لنسخة الويب.

### 4.1 المؤقت الموثوق والإشعارات (Module 1: Reliable Timer & Notifications)

* **مصدر الحقيقة:** المؤقت محسوب من `focusEndsAt` محفوظ في التخزين — يعمل مع زر الرئيسية، قفل الشاشة، والإغلاق الكلي.
* **إشعار ثابت أثناء الجلسة:** "🎯 اسم المهمة" + عدّاد تنازلي حيّ (`showChronometer`).
* **إشعار الانتهاء:** بصوت واهتزاز على قناة High Importance: *"✅ انتهت جلسة: اسم المهمة"*.
* **الانتهاء خارج التطبيق:** تُسجَّل الجلسة مكتملة عند العودة مع رسالة "انتهت الجلسة".
* **الإيقاف والاستئناف:** الإيقاف يلغي الإشعارات ويحفظ المتبقي؛ الاستئناف يولّد `focusEndsAt` جديداً ويعيد الجدولة.
* **الأذونات:** طلب إذن الإشعارات عند أول تشغيل.

### 4.2 النسخ الاحتياطي (Module 2: JSON Backup)

* تصدير/استيراد JSON من الإعدادات لكل المتاجر عبر المشاركة.
* الاستيراد استبدال كامل بعد تأكيد صريح.

### 4.3 إضافات البروتوكول (Module 3: INTJ Protocol Add-ons)

* **تحذير الاستنزاف:** عند بدء كتلة 90 دقيقة على مهمة `drain` → تحذير + اقتراح تأجيلها لآخر اليوم.
* **تنبيه "اكتفيت":** بعد آخر كتلة عميقة ضمن الحد الحالي (ديناميكي 2–4 — Module 5).
* **استراحة تلقائية:** مؤقت 20 دقيقة بعد كل كتلة + إشعار "عُد".
* **التقاط الأفكار:** زر 💡 في FocusCard يحفظ الفكرة في Vault بنقرة ويعيد إلى الكتلة.
* **إشعاران يوميان قابلان للضبط:** صباحي (NeuroGate) ومسائي (الإغلاق).
* **أهداف الجودة:** Velocity ≥ 70% و Quality Gate ≥ 80% في CompletionPanel بتلوين أحمر/أخضر.
* **🔋 شحن:** خانة يومية ضمن عادات المساء.
* **المراجعة الأسبوعية:** إشعار أسبوعي ثابت.

### 4.4 مؤشرات الإنجاز (Module 4: Output Metrics)

* **دقائق العمل العميق المنجز يومياً:** كتل مكتملة على `genius`/`neutral` اجتازت DoD (تُستبعد الملغاة والمسقطة).
* **نسبة الضفادع المنجزة أسبوعياً:** أيام اجتاز فيها ضفدع الأولوية #1 الـ DoD ÷ أيام الأسبوع.
* **العرض:** رقم اليوم في المحطة المسائية + اتجاه 7/30 يوماً في CompletionPanel.

### 4.5 الضبط التلقائي للحمل (Module 5: Auto-Tuning)

* **المدخلات (آخر 7 أيام):** نسبة إكمال الكتل · عدد RCA C · Energy Flow Index.
* **القواعد:**

| الحالة | الشرط | الإجراء المقترح |
| --- | --- | --- |
| رفع | إكمال ≥ 90% و RCA C = 0 واستنزاف < 20% | كتلة إضافية أو 60→90 |
| ثبات | إكمال 70–90% | لا تغيير |
| خفض | إكمال < 70% أو RCA C ≥ 3 أو استنزاف > 30% | كتلة أقل أو 90→60 |

* **سقف مطلق:** 4 كتل عميقة يومياً.
* **العرض:** اقتراح في المحطة الصباحية (قبول/رفض بنقرة)، لا تغيير صامت.

### 4.6 الأولويات الثابتة المرتبطة بالمشاريع (Module 6: Anchored Priorities)

* **الأولوية الثابتة (Anchor):** تستمر يومياً حتى تُغلق يدوياً — مثال: "دراسة الألمانية A2".
* **الحد:** 3 أولويات ثابتة كحد أقصى، كل أولوية مرتبطة بمشروع واحد (1:1).
* **سحب المهام:** زر "＋ سحب مهمة" تحت كل أولوية يعرض مهام TODO من مشروعها فقط؛ حتى 3 مهام يومياً لكل أولوية.
* **الأهداف:** للأولوية هدف بعيد + تاريخ؛ لكل مهمة مسحوبة DoD خاص.
* **الطاقة:** تصنيف الطاقة على المهمة؛ حد `drain` الواحد يُحسب على المهام.
* **التنفيذ:** بدء الكتلة يختار مهمة من تحت أولوية؛ المؤقت والإشعار: "🎯 الأولوية › المهمة".
* **الإغلاق والترحيل:**
  * المهمة المنجزة → DONE في المشروع الأصلي.
  * غير المنجزة → تُرحّل لليوم التالي تحت الأولوية بعلامة "مُرحّلة ×N".
  * عند 3 ترحيلات يقترح التطبيق Conscious Drop.
* **الضفدع:** أول مهمة تحت الأولوية #1؛ إعادة الترتيب بالسحب.
* **العزل:** المشاريع غير المرتبطة بأولوية تبقى في شاشة المشاريع ولا تظهر في شاشة اليوم.

### 4.7 حارس التركيز (Module 7: Focus Guard)

* **حارس الخروج:** عند مغادرة التطبيق أثناء كتلة (المؤقت يتوقف) → إشعار فوري *"🎯 الأولوية › المهمة — متوقفة عند mm:ss، عُد"*. تذكير ثانٍ بعد دقيقتين وثالث بعد 5 دقائق ثم يتوقف. النقر يفتح FocusCard ويستأنف.
* **الشاشة مضاءة:** طوال الكتلة عبر `expo-keep-awake`.
* **لا تزعجني:** زر عند بدء الكتلة يفتح إعدادات Do Not Disturb في Android بنقرة (`Linking.sendIntent('android.settings.ZEN_MODE_SETTINGS')`)، مع تذكير مرة واحدة يومياً فقط.

### 4.8 كشف التشتت ومسار العودة (Module 8: Distraction Detection & 🧭 Recovery)

* **الكشف التلقائي** — يكفي تحقق شرط واحد:
  1. خروجان أو أكثر من التطبيق في الكتلة نفسها.
  2. إيقاف مؤقت > 5 دقائق.
  3. مرور 30 دقيقة على المحطة الصباحية بلا بدء كتلة.
  4. ترك الكتلة بعد < 10 دقائق من بدايتها.
* **الزر اليدوي:** زر "😵 مشتت" دائم في FocusCard.
* **بطاقة "🧭 العودة"** — خطوات متتالية، كل خطوة نقرة واحدة:
  1. **سمِّ المشتت:** هاتف / فكرة / شخص / ملل / تعب / قلق → يُسجَّل.
  2. **أفرغه:** فكرة → Vault · تعب → استراحة 5 دقائق · قلق → سطر واحد في Journal · هاتف/ملل/شخص → تخطٍّ.
  3. **أصغر خطوة تالية:** عرض DoD المهمة + حقل "أول فعل خلال دقيقتين" (يُقترح تلقائياً آخر خطوة محفوظة للمهمة).
  4. **كتلة إقلاع 10 دقائق** على المهمة نفسها؛ عند انتهائها: "أكمل الكتلة الأصلية؟" (نعم = يستأنف الوقت المتبقي).
* **سلّم التصعيد:**
  * التشتت الثالث في اليوم → اقتراح تبديل المهمة إلى `neutral` أو تقصير الكتلة 90→45.
  * الرابع → اقتراح 🔋 شحن 20 دقيقة.
* **سجل المشتتات:** أعلى 3 مشتتات أسبوعياً + عدد مرات العودة الناجحة في المراجعة الأسبوعية، مع اقتراح وقائي واحد لكل مشتت متكرر.
* **زمن العودة:** مؤشر في CompletionPanel = متوسط الدقائق من كشف التشتت حتى استئناف العمل.

### 4.9 تقليص حجم الحزمة (Module 9: APK Size)

* معمارية واحدة `arm64-v8a` عبر `ORG_GRADLE_PROJECT_reactNativeArchitectures` في `eas.json` (profile `personal`).
* `enableProguardInReleaseBuilds: true` و `enableShrinkResourcesInReleaseBuilds: true` عبر `expo-build-properties`.

## 5. نموذج البيانات (Data Model — TypeScript)

```ts
type Energy = 'genius' | 'neutral' | 'drain';

interface AnchorPriority {
  id: string;
  projectId: string;        // 1:1 مع مشروع
  title: string;
  goal: string;             // الهدف البعيد
  targetDate: string;       // ISO date
  order: 1 | 2 | 3;
  closedAt?: string;
}

interface PulledTask {
  id: string;
  priorityId: string;
  projectTaskId: string;    // المهمة الأصلية في المشروع
  dod: string;              // إلزامي
  energy: Energy;
  date: string;
  order: number;            // الأول تحت الأولوية #1 = الضفدع
  rolloverCount: number;    // 3 → اقتراح Conscious Drop
  nextStep?: string;        // آخر "أول فعل خلال دقيقتين"
  status: 'todo' | 'done' | 'dropped';
}

interface FocusSession {
  id: string;
  taskId: string;
  blockMinutes: 90 | 60 | 45 | 20 | 10;
  focusEndsAt: number;      // epoch ms — مصدر الحقيقة
  pausedRemainingMs?: number;
  exits: number;
  status: 'running' | 'paused' | 'done' | 'failed' | 'cancelled';
}

interface DistractionEvent {
  id: string;
  sessionId?: string;
  at: number;
  trigger: 'exits' | 'pause' | 'no-start' | 'early-quit' | 'manual';
  kind?: 'phone' | 'idea' | 'person' | 'boredom' | 'fatigue' | 'anxiety';
  resumedAt?: number;       // لحساب زمن العودة
}

interface DailyMetrics {
  date: string;
  deepMinutes: number;
  frogDone: boolean;
  completionRate: number;
  rcaC: number;
  drainPct: number;
  avgReturnMin: number;
}

interface TuningSuggestion {
  date: string;
  change: 'up' | 'hold' | 'down';
  accepted?: boolean;
}
```

## 6. المتطلبات غير الوظيفية (Non-Functional Requirements)

1. **دقة المؤقت:** ±1 ثانية بعد قفل الشاشة أو الإغلاق الكلي.
2. **العمل دون إنترنت:** كل الميزات تعمل محلياً.
3. **الخصوصية:** البيانات محلية فقط، عدا المزامنة الحالية.
4. **حجم الحزمة:** هدف ≤ 35MB.
5. **الإشعارات:** عربية وتحمل اسم المهمة دائماً.
