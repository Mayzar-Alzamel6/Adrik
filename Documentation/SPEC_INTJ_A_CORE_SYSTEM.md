## 1. الهدف (Objective)

ترقية وتوحيد المنظومة المركزية لنظام «أدرك OS» (`adrik-personal`) لتصبح هي نفسها نظام تشغيل `INTJ-A` الأصلي؛ بحيث تعالج برمجياً وسلوكياً المعضلة التأسيسية بين:
1. **حماية الطاقة الإدراكية:** فلترة ما يدخل النظام ومواءمته مع نطاق العبقرية الفطرية (`Zone of Genius`) وتجنب استنزاف المهام الروتينية (`Drain`).
2. **حوكمة غريزة إغلاق الدوائر (Closure Governance):** ترويض الرغبة القهرية في الشطب السريع عبر فرض معيار الاكتمال النوعي (`definitionOfDone`)، وبوابة تأكيد الإتقان، واستيعاب الطوارئ بمرونة خوارزمية (`Agile Reroute`)، وتجميد الأفكار المعمارية، ودمج كتل التركيز ومؤشرات الرافعة العالية مباشرة في التدفق اليومي والأسبوعي، مع إلغاء التبويب المنفصل.

## 4. تفاصيل الوحدات والقدرات (Detailed Module Specifications)

### Module 1: `core-types-and-store`
* **المسؤولية:** تحديث الأنواع في TypeScript والحالة في Zustand.
* **البيانات المضافة للـ PriorityItem:**
  ```typescript
  export type EnergyTaxonomy = 'genius' | 'drain' | 'neutral';

  export interface PriorityItem {
    id: string;
    text: string;
    completed: boolean;
    definitionOfDone?: string;       // معيار الاكتمال الإلزامي
    energyTag?: EnergyTaxonomy;       // وسم الطاقة
    isRerouted?: boolean;             // هل تم ترحيلها كطوارئ
    isDropped?: boolean;              // هل تم إسقاطها بوعي / تفويض
    dropReason?: string;
  }
  ```
* **البيانات المضافة للـ ArchitectVaultItem:**
  ```typescript
  export interface ArchitectVaultItem {
    id: string;
    title: string;
    realProblem: string;              // المشكلة الحقيقية
    mechanism: string;                // كيف تعمل في جملتين
    roiReason: string;                // العائد على الاستثمار مقارنة بالأولويات
    createdAt: string;                // تاريخ الإيداع
    lockedUntil: string;              // قفل 48 ساعة
    status: 'locked' | 'unlocked' | 'promoted' | 'discarded';
  }
  ```
* **البيانات المضافة لسجل الطوارئ ومؤشرات الأسبوع:**
  ```typescript
  export interface RerouteEvent {
    id: string;
    date: string;
    incident: string;                 // وصف العارض الطارئ في سطر
    negotiatedHours: number;          // الساعات المقتطعة
    bufferTarget: 'tonight' | 'tomorrow'; // جهة الترحيل
    timestamp: string;
  }
  ```

### Module 2: `priorities-and-governance`
* **المسؤولية:** حوكمة إدخال وإغلاق الضفادع اليومية الثلاثة في `PrioritiesCard.tsx`.
* **القواعد الصارمة:**
  1. **حقل الـ DoD الإلزامي:** لا يمكن تفعيل الضفدع دون إدخال شرط اكتمال ثنائي واضح.
  2. **قفل الطاقة الصارم (Energy Constraint):** النظام يمنع برمجياً اختيار وسم `drain` لأكثر من ضفدع واحد من الثلاثة. إشعار فوري: *"طاقتك الإدراكية ثمينة، لا يُسمح بأكثر من مهمة استنزاف واحدة يومياً"*.
  3. **بوابة تأكيد الإتقان (Mastery Gate):** عند الضغط على إنهاء المهمة، تنبثق نافذة مصغرة:
     *"هل تم استيفاء معيار الـ DoD التالي بنسبة 100%؟"* [أؤكد الإتقان والامتثال] مقابل [متابعة العمل].
  4. **بروتوكول الإلغاء الواعي / التفويض (Kill / Outsource):** خيار متاح بجانب كل مهمة لإسقاطها وشطبها رسمياً دون خصم نقاط أو ذنب، مع تسجيل السبب كقرار رافعة عليا.

---

### Module 3: `agile-reroute`
* **المسؤولية:** امتصاص الصدمات وحالات الطوارئ في `AgileRerouteModal.tsx`.
* **التدفق:**
  1. زر [تعديل مسار طارئ / Agile Reroute] بجانب شريط الأولويات.
  2. نموذج سريع من 3 مدخلات:
     - وصف العارض الطارئ (سطر واحد).
     - الوقت المقتطع (مثلاً: ساعتان).
     - توجيه الساعات المتبقية إلى خانة الـ Buffer (مساء اليوم أو غداً).
  3. عند الحفظ: يعاد ضبط مؤقتات اليوم ويوضع وسم `🔄 مسار مُعاد تكييفه` دون تسجيل فشل أو تصفير للعدادات.

---

### Module 4: `focus-and-rca-integration`
* **المسؤولية:** دمج تجربة كتل التركيز المنضبطة وتحليل الأعطال في `FocusCard.tsx` و `TodayView.tsx`.
* **المواصفات:**
  1. استبدال المؤقت الحر القديم بـ 3 كتل ثابتة قابلة للاختيار:
     - الكتلة 1: **90 دقيقة** (الضفدع الأساسي).
     - الكتلة 2: **60 دقيقة** (المهمة الثانية).
     - الكتلة 3: **45 دقيقة** (الالتزام الثالث أو الإغلاقات).
  2. تضمين عقد الانطلاق السريع لكل كتلة (`Done When` + `Out of Scope`).
  3. زر استدعاء [معالج الأعطال السريع / 2-Min RCA Triage] فور التعثر أو انتهاء الوقت:
     - Bug A: هندسة مفرطة وتشعب.
     - Bug B: ضبابية معيار الإنجاز.
     - Bug C: انخفاض الطاقة والتركيز.
     مع إظهار الترقيع البرمجي الفوري (Executable Patch) بضغطة زر.
  4. إزالة خيار تبويب "بروتوكول INTJ" المنفصل من شريط محطات `TodayView` ليصبح هو قلب تجربة التركيز الأساسية.

### Module 5: `architect-sandbox`
* **المسؤولية:** تحييد النزوات المعمارية في `DelayVaultModal.tsx`.
* **المواصفات:**
  1. إضافة تبويب ثالث في الصندوق باسم: `Architect Sandbox`.
  2. الحقول الثلاثة الإلزامية:
     - المشكلة الحقيقية (Real Problem).
     - الآلية المختصرة (Mechanism in 2 lines).
     - العائد على الاستثمار والرافعة (ROI vs current priorities).
  3. قفل زمني تلقائي لمدة **48 ساعة** مع عداد تنازلي وشارة: *"أفكارك المعمارية قيمة، دعها تنضج 48 ساعة لتفصل الحماس اللحظي عن الجدوى الحقيقية"*.

### Module 6: `ai-reframer-tuning`
* **المسؤولية:** ضبط موجه الذكاء الاصطناعي في `coach.ts` ومثلث الإدراك.
* **المواصفات:**
  1. موجه النظام: ضبط الهوية لتكون `Senior Systems Architect & Algorithmic Debugger`.
  2. القواعد:
     - حظر عبارات التعاطف الإنشائية أو الدعم العاطفي العام.
     - صياغة أي تعثر فكري كـ `Logical Bug / Cognitive Glitch` وتحديد السطر المشوه بدقة.
     - استبدال التشوه بخطوة تصحيحية تنفيذية محددة: `Executable Patch / Next Physical Action`.

### Module 7: `audit-and-metrics`
* **المسؤولية:** الرقابة والقياس الأسبوعي في `EveningClosure.tsx` و `CompletionPanel.tsx`.
* **المواصفات:**
  1. **محطة المساء:** إضافة سؤال فحص الجودة الثنائي (0 أو 1):
     `[ ] فحص الجودة: هل نُفذت مهام اليوم بإتقان واستيفاء للـ DoD أم مجرد شطب سريع؟`
  2. **مراجعة الجمعة:**
     - مؤشر **سرعة الرافعة العالية (High-Leverage Velocity):** نسبة مهام الرافعة والعقد الأساسية المنجزة مقارنة بالمهام الهامشية.
     - مؤشر **التوازن الطاقي (Energy Flow Index):** نسبة مهام `Zone of Genius` مقابل مهام `Drain` خلال الأسبوع، للتنبيه عند تجاوز نسبة الاستنزاف 30%.

## 5. أسلوب الكود والهوية البصرية (Code Style & UX)

* **لغة الواجهة:** دعم كامل للغة العربية (100% RTL).
* **الهوية البصرية:** مظهر هادئ ونظيف (Zen Paper Aesthetics) يتماشى مع لوحة ألوان التطبيق الحالية (Stone / Slate / Neutral).
* **الكتابة الصارمة:** TypeScript strict بدون `any`، مع تعريف واجهات محكمة لكل نوع جديد.

## 6. استراتيجية الاختبار والتحقق (Testing Strategy)

* **التحقق من البناء:** `npm run build` يجب أن يجتاز بنجاح دون أخطاء في الـ Types أو الصفحات.
* **التحقق من استمرارية البيانات (Persistence):** اختبار دورة قراءة وكتابة البيانات في `localStorage` للتأكد من عدم كسر الحسابات القديمة.
* **التحقق من القفل الطاقي:** التأكد البرمجي من منع اختيار أكثر من مهمة واحدة `drain` في نفس اليوم.

---

## 7. الضوابط الحاكمة (Boundaries)

* **Always:**
  - فحص `npm run build` واجتياز تدقيق TypeScript عند كل خطوة.
  - الحفاظ على سلامة بيانات المستخدم السابقة في `localStorage`.
  - اعتماد التصميم الهادئ Zen Paper واتجاه الـ RTL.
* **Ask First:**
  - حذف أو تعديل أي مسارات أو صفحات أخرى خارج نطاق شاشات اليوم والمراجعة وصندوق النزوات.
* **Never:**
  - لمس تطبيق الهاتف `adrik-mobile`.
  - إضافة أي مكتبات خارجية ثقيلة غير ضرورية.

## 8. معايير النجاح القابلة للقياس (Success Criteria)

1. إتاحة حقل `definitionOfDone` وتصنيف الطاقة في الأولويات، ومنع النظام اختيار أكثر من مهمة `drain` واحدة.
2. عمل بوابة تأكيد الإتقان قبل شطب أي مهمة بنجاح.
3. تشغيل معالج `Agile Reroute` لترحيل الطوارئ دون تصفير العدادات أو تسجيل فشل.
4. ظهور المؤقتات الثابتة (90/60/45) وعقد الانطلاق والـ RCA في شاشة التركيز الرئيسية، وإزالة التبويب الرابع المزدوج من `TodayView`.
5. تشغيل مستودع `Architect Sandbox` وقفل الـ 48 ساعة بنجاح داخل صندوق النزوات.
6. استجابة الذكاء الاصطناعي بنبرة مهندس النظم وتصحيح الأعطال المنطقية.
7. ظهور فحص الجودة المسائي ومؤشري الرافعة والتوازن الطاقي في تقرير الجمعة.
8. اكتمال البناء `npm run build` بنجاح تام وبصفر أخطاء.
