## 1. الافتراضات الحاكمة (Surface Assumptions)

1. **الواجهة موحدة 100%:** لا يوجد نسخ أو تفريع لشاشات التطبيق (No Forked Layouts). التكيّف يتم عبر طبقة تكوين حالة (State Configuration) تتحكم في قيم البارامترات، والنصوص، ونوع بطاقات التدخل.
2. **المبادئ المنهجية مقدسة:** قاعدة الـ 3 أولويات، وبوابة التركيز (Neuro-Gate)، وعدم تصفير العدادات عند التعثر ثابتة في كل الأنماط دون استثناء.
3. **التشخيص اختياري وسريع:** مدة الاختبار 2-3 دقائق (5-6 أسئلة إجرائية)، مع إمكانية التخطي أو إعادة التقييم أو تعديل البارامترات يدوياً في أي وقت من الإعدادات.
4. **تخزين الحالة:** تخزين النمط والبارامترات في Zustand Store محلي (`localStorage`) متصل بنموذج المستخدم في قاعدة البيانات عبر Prisma لضمان العمل Offline و Online.

---

## 2. الهدف ونطاق العمل (Objective & Scope)

### الهدف:
تمكين تطبيق "أدرك" من قراءة النمط السلوكي والتنفيذي للمستخدم وتكييف تجربة العمل تلقائياً، بحيث يتم ضبط:
1. **إيقاع الكتل الزمنية (Time-Block Pacing)**.
2. **صرامة ولغة شريك المحاسبة الذكي (Accountability Tone)**.
3. **تكتيك كسر التسويف السريع (Friction Breaker Action)**.
4. **كثافة عناصر الواجهة (UI Density & Minimal Focus)**.

وذلك لزيادة استمرارية المستخدم وخفض معدل التراجع والنفور النفسي دون التنازل عن الانضباط الصارم.

## 3. الأنماط السلوكية التنفيذية الأربعة (Behavioral Execution Archetypes)

```
                              │
          ┌───────────────────┴───────────────────┐
          ▼                                       ▼
  [ دافعية داخلية / منطقية ]              [ دافعية خارجية / مرنة ]
          │                                       │
   ┌──────┴──────┐                         ┌──────┴──────┐
   ▼             ▼                         ▼             ▼

```

| :--- | :--- | :--- | :--- | :--- |
| **1. المخطط الاستراتيجي (The Strategic Architect)** | الهندسة المفرطة وشلل البحث المتشعب | كتل عميقة: 90 / 60 / 45 دقيقة | تحليلية جافة، أرقام، RCA لتشخيص الأعطال | إلزام بكتابة شرط الإغلاق الثنائي (Done When) |
| **2. المندفع السريع (The Fast Sprinter)** | سرعة التشتت وضعف التحمل العصبي الطويل | كتل رشيقة: 25 دقيقة (بومودورو أدرك) + 5 دقائق راحة | تشجيعية سريعة، احتفال بالانتصارات الصغيرة | زر "أصغر خطوة ممكنة" (2 دقيقة) + سلة تفريغ الأفكار |
| **3. المثالي المتوجس (The Anxious Perfectionist)** | رعب البدايات الناقصة وجلد الذات عند التعثر | كتل تدرجية: 20 دقيقة تسخين ثم 40 دقيقة | هادئة، خافضة للتوتر، تركيز على الاستئناف الفوري | مبدأ "المسودة الأولى المشوهة" (Shitty First Draft) |
| **4. المستجيب للمسؤولية (The External Obliger)** | التسويف في المهام الذاتية وغياب الرقابة | كتل موقوتة بمواعيد استحقاق ثابتة | "الشريك الشحيح الصارم" — تذكير قاطع بتكلفة الإخفاق | محاكاة الالتزام الخارجي وإلزام برفع تقرير فوري |

## 4. نموذج الاختبار التشخيصي (Onboarding Diagnostic Questions)

يتكون الاختبار من 5 أسئلة مباشرة تركز على الوقائع السلوكية وليس التفضيلات النظرية:

1. **س1 (طبيعة البدء):** عندما تقف أمام مهمة كبرى وجديدة، ما هو أول عائق يوقفك؟
   * أ) الرغبة في التخطيط والبحث أكثر وجمع المراجع قبل كتابة حرف. *(Architect)*
   * ب) الشعور بالملل والنفور فور الجلوس والبحث عن شيء مسلٍ. *(Sprinter)*
   * ج) الخوف من ألا تخرج المهمة بالمستوى المطلوب أو المثالي. *(Perfectionist)*
   * د) تأجيلها لأن أحداً لا ينتظرها مني اليوم تحديداً. *(Obliger)*

2. **س2 (التحمل العصبي للتركيز):** ما هي أقصى مدة يمكنك البقاء فيها بكامل تركيزك دون فقدان الاتصال الذهني؟
   * أ) أستطيع الغوص لساعة ونصف إذا كانت الصورة واضحة. *(Architect)*
   * ب) بعد 20-30 دقيقة أحتاج للحركة أو أشتت ذهني تلقائياً. *(Sprinter)*
   * ج) أبدأ بصعوبة شديدة وقلق، لكن إن بدأت أستمر باعتدال. *(Perfectionist)*
   * د) حسب وجود موعد تسليم حرج يضغط عليّ. *(Obliger)*

3. **س3 (التعامل مع التعثر):** إذا انقطعت عن الخطة ليومين متتاليين، ما الذي يحدث غالباً؟
   * أ) أراجع النظام لأعرف الثغرة المنطقية في التخطيط وأعيد هندسته. *(Architect)*
   * ب) أنسى ما كنت أفعله كلياً وأتحمس لفكرة جديدة ومختلفة. *(Sprinter)*
   * ج) يجتاحني إحباط وجلد ذات وأشعر أن البداية فسدت بالكامل. *(Perfectionist)*
   * د) أعود فقط إذا وجدت من يسألني أو كان هناك موعد قادم. *(Obliger)*

4. **س4 (نوع المحاسبة الفعال):** أي نوع من التنبيهات يدفعك للحركة فعلياً؟
   * أ) أرقام وبيانات موضوعية توضح لي أين ضاع وقتي بدقة. *(Architect)*
   * ب) تنبيه مرح ولطيف يحفزني على إنهاء دورة بومودورو واحدة الآن. *(Sprinter)*
   * ج) رسالة هادئة تذكرني بأن الخطوة الصغيرة اليوم كافية والكمال غير مطلوب. *(Perfectionist)*
   * د) مواجهة صريحة وحازمة تذكرني بالتزامي وتهديد إهدار عمري. *(Obliger)*

5. **س5 (تفريغ المشتتات):** ما أكثر ما يقطع حبل أفكارك أثناء العمل؟
   * أ) الرغبة في فحص معلومة تقنية فرعية والتعمق فيها لساعات. *(Architect)*
   * ب) إشعارات الهاتف والأفكار المفاجئة غير المرتبطة بالعمل. *(Sprinter)*
   * ج) التردد في اتخاذ القرار وإعادة صياغة نفس الجملة/الكود عدة مرات. *(Perfectionist)*
   * د) طلبات الآخرين ومقاطعات البيئة المحيطة. *(Obliger)*

## 5. المعمارية التقنية (Technical Stack & Architecture)

* **البيئة البرمجية القائمة:**
  * Framework: Next.js 15.1.7 (App Router), React 19.

## 6. عقود البيانات والأنواع (TypeScript Types)

```typescript
// src/types/behavioral.ts

export type ExecutionArchetype = 
  | 'ARCHITECT'      // المخطط الاستراتيجي
  | 'SPRINTER'       // المندفع السريع
  | 'PERFECTIONIST'  // المثالي المتوجس
  | 'OBLIGER';       // المستجيب للمسؤولية

export interface BehavioralConfig {
  archetype: ExecutionArchetype;
  confidenceScore: number; // 0 - 100%
  timerPacing: {
    blocks: number[]; // e.g. [90, 60, 45] or [25, 25, 25, 25]
    breakMinutes: number;
    autoBreak: boolean;
  };
  accountability: {
    tone: 'analytical' | 'encouraging' | 'gentle_recovery' | 'firm_strict';
    nudgeFrequency: 'low' | 'moderate' | 'high';
  };
  frictionBreaker: {
    defaultTactic: 'strict_rca' | 'two_minute_step' | 'ugly_draft' | 'commitment_contract';
    allowParkingLot: boolean;
  };
  uiDensity: 'compact_zen' | 'standard' | 'metrics_heavy';
}
```

## 8. إستراتيجية الاختبار (Testing Strategy)

1. **اختبار خوارزمية التشخيص (Unit Tests):**
   * ملف: `tests/behavioral-diagnostic.test.mjs`
   * التحقق من أن تجميع إجابات الأسئلة الخمسة يعيد بدقة النمط الصحيح لكل توليفة إجابات.
   * التحقق من السلوك الافتراضي عند وجود تعادل بين نمطين (Fallback / Primary tie-break).
2. **اختبار محرك التكيّف (Adapter Engine Tests):**
   * التحقق من أن كل `ExecutionArchetype` يعيد `BehavioralConfig` مكتمل وصحيح ومطابق للنوع.
3. **اختبار التخزين والاسترجاع (Persistence):**
   * التحقق من حفظ واسترجاع النمط والإعدادات في `localStorage` دون تسريب أو انهيار عند البيانات التالفة.

## 9. الحدود الصارمة (Boundaries)

* **دائماً (Always):**
  * إبقاء واجهة التطبيق موحدة بالكامل والتكيّف من خلال الخصائص والـ props فقط.
  * كتابة اختبارات خوارزمية التشخيص قبل دمج الكود.
  * توفير زر "تعديل يدوي" يمنح المستخدم حرية ضبط أوقات الكتل ونبرة المحاسبة بما يناسبه إن أراد.
* **اسأل أولاً (Ask First):**
  * إضافة حقول جديدة في Prisma schema تتطلب ترحيل قاعدة البيانات (`prisma db push`).
  * تعديل منطق المتجر الرئيسي القائم `useAppStore.ts`.
* **إياك أن تفعل (Never):**
  * بناء شاشات كاملة مكررة كودياً لكل شخصية.
  * السماح بتعطيل بوابة التركيز (Neuro-Gate) أو قاعدة الـ 3 أولويات تحت دعوى التخصيص.
  * كتابة كود تنفيذي قبل اعتماد هذه المواصفة.
